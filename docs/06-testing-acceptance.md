# 06. 테스트 및 최종 검수 기준

## 1. 기능 테스트

| ID | 테스트 상황 | 기대 결과 |
|---|---|---|
| T-01 | 긍정 문장 입력 | 긍정 라벨, 신뢰도, 분석 이유 표시 |
| T-02 | 부정 문장 입력 | 부정 라벨, 신뢰도, 분석 이유 표시 |
| T-03 | 중립 문장 입력 | 중립 라벨, 신뢰도, 분석 이유 표시 |

| T-12 | AI 이유에 HTML 문자열 포함 | HTML로 실행되지 않고 텍스트로 표시 |

## 2. UI 검수
- [ ] 360px 너비에서 가로 스크롤이 없다.
- [ ] 입력창과 분석 버튼을 쉽게 찾을 수 있다.
- [ ] 입력창 글자 수가 정확히 갱신된다.
- [ ] 로딩 상태가 눈에 보인다.
- [ ] 결과의 감성 라벨·신뢰도·분석 이유가 구분된다.
- [ ] 오류 메시지가 사용자가 이해할 수 있는 한국어로 표시된다.
- [ ] 키보드만으로 입력과 분석이 가능하다.
- [ ] 포커스 표시와 텍스트 대비가 유지된다.
- [ ] 첨부 이미지의 레이아웃 특징을 참고하되 금융 앱 디자인을 복제하지 않았다.

## 3. 보안 검수
- [ ] OpenAI 키가 프론트엔드 파일에 없다.
- [ ] Supabase service role key가 프론트엔드 파일에 없다.
- [ ] `.env`가 Git에 포함되지 않는다.
- [ ] 서버 로그에 사용자 원문과 비밀 키가 기록되지 않는다.
- [ ] AI가 반환한 텍스트를 HTML로 직접 삽입하지 않는다.
- [ ] 서버에서 입력과 AI 응답을 모두 검증한다.

## 4. 실행 및 배포 검수
- [ ] 새 환경에서 문서대로 의존성을 설치할 수 있다.
- [ ] 로컬에서 메인 화면이 열린다.
- [ ] 로컬에서 API 요청이 정상 작동한다.
- [ ] Vercel 배포가 성공한다.
- [ ] 배포 환경 변수 설정 후 실제 분석이 작동한다.

## 5. 완료 판정
다음 조건을 모두 만족해야 완료로 판정한다.
1. 필수 기능 FR-01~FR-05가 구현되어 있다.
2. 기능 테스트 T-01~T-12의 결과가 기록되어 있다.
3. UI·보안·배포 체크리스트에 미완료 항목이 없다. 외부 설정 때문에 실행할 수 없는 항목은 미완료 사유와 필요한 작업을 명시한다.
4. 문서에 없는 기능을 임의로 추가하지 않았다.
5. 완료 보고에 변경 파일, 실행 방법, 검증 결과, 남은 제한 사항이 포함되어 있다.
