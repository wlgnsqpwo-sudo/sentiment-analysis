# 02. UI 구현 지침

## 1. 참고 이미지 해석
첨부된 이미지는 모바일 앱의 메뉴 화면이다. 다음과 같은 **구조와 분위기만** 참고한다.
- 밝은 회색에 가까운 페이지 배경과 흰색 카드
- 상단의 간결한 헤더와 아이콘 버튼
- 둥근 모서리와 넉넉한 내부 여백
- 작은 바로가기 영역과 둥근 보조 메뉴 칩
- 제목으로 구분되는 콘텐츠 영역
- 화면 하단의 고정 내비게이션

금융 앱의 로고, 명칭, 계정 정보, 메뉴 텍스트, 아이콘 조합을 그대로 복사하지 않는다. 감성 분석 서비스의 목적에 맞게 새롭게 구성한다.

## 2. 화면 구성
### 상단 헤더
- 왼쪽: 서비스 이름 또는 간단한 심볼
- 오른쪽: 도움말 아이콘 등 실제 동작이 있는 버튼만 배치
- 헤더 높이는 모바일에서 약 56~64px 범위로 유지한다.

### 소개 영역
- 제목 예시: `텍스트의 감정을 분석해 드려요`
- 설명: `문장을 입력하면 긍정, 부정, 중립 결과와 분석 이유를 확인할 수 있어요.`
- 장황한 설명은 피하고 입력 영역을 빠르게 찾을 수 있게 한다.

### 입력 카드
- 흰색 카드 안에 텍스트 입력창과 글자 수 표시를 배치한다.
- 입력창은 여러 줄을 입력할 수 있어야 한다.
- placeholder 예시: `분석할 문장을 입력해 주세요.`
- 카드 하단에 `감성 분석하기` 주요 버튼을 둔다.
- 버튼은 충분한 대비를 갖고 전체 폭으로 표시한다.

### 빠른 예시 영역
- 필요하면 `예시 문장` 칩을 2~3개 제공할 수 있다.
- 예시 칩을 누르면 입력창에 문장이 채워져야 한다.
- 예시 문장은 실제 분석 결과를 미리 보여주는 가짜 결과와 연결하지 않는다.

### 결과 카드
- 분석 완료 후 입력 카드 아래에 표시한다.
- 감성 라벨을 가장 먼저 보여주고 신뢰도와 분석 이유를 계층적으로 배치한다.
- 긍정/부정/중립은 색상뿐 아니라 텍스트로 명시한다.
- 결과가 없을 때 빈 결과 카드를 미리 노출하지 않는다.
- 분석 중에는 결과 영역에 로딩 상태를 표시한다.

### 하단 영역
- 첨부 이미지처럼 하단 고정 내비게이션을 사용할 수 있으나, 실제 기능이 없는 메뉴를 클릭 가능한 것처럼 만들지 않는다.
- MVP에서 단일 페이지만 제공한다면 하단에는 `분석`, `이용 안내`처럼 실제 섹션으로 이동하는 항목만 둔다. 구현하지 않은 메뉴는 제외한다.

## 3. 디자인 토큰
초기값이며 실제 화면을 보며 일관되게 적용한다.
```css
:root {
  --color-page: #f5f5f7;
  --color-surface: #ffffff;
  --color-text: #202124;
  --color-muted: #777b83;
  --color-primary: #6c35d8;
  --color-border: #ececf0;
  --radius-card: 18px;
  --radius-control: 12px;
  --space-page: 16px;
  --shadow-card: 0 3px 14px rgba(20, 20, 30, 0.04);
}
```
감성 결과 색상은 접근성을 고려해 텍스트 대비를 확보한다. 특정 색상은 참고용이며 색상만으로 의미를 전달하지 않는다.

## 4. 반응형 기준
- 360px 너비: 좌우 여백 16px, 카드 폭은 화면에 맞게 줄어든다.
- 768px 이상: 입력·결과 콘텐츠의 최대 폭을 약 720px로 제한하고 가운데 정렬한다.
- 1024px 이상: 불필요하게 넓어지지 않도록 콘텐츠 폭을 제한한다.
- 고정 하단 영역은 입력창이나 결과 내용을 가리지 않도록 본문 아래쪽에 충분한 여백을 둔다.

## 5. 접근성
- 입력창에는 화면에 보이는 label을 연결한다.
- 버튼은 키보드로 실행할 수 있어야 한다.
- 로딩·결과·오류 상태는 스크린 리더가 인식할 수 있도록 적절한 live region을 사용한다.
- 포커스 표시를 제거하지 않는다.
- 본문 글자와 배경의 명도 대비를 충분히 확보한다.

## 완료 기준
- 모바일 360px에서 가로 스크롤이 없다.
- 입력, 분석 버튼, 결과 카드가 시각적으로 구분된다.
- 첨부 이미지의 카드·여백·헤더 구조를 참고하되 서비스에 맞는 독자적 UI다.
- 로딩, 결과, 오류 상태가 각각 구분된다.
