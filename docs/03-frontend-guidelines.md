# 03. 프론트엔드 구현 지침

## 파일 책임
- `index.html`: 화면의 의미 구조와 접근성 레이블
- `public/css/styles.css`: 색상, 간격, 카드, 반응형 스타일
- `public/js/app.js`: 입력 검사, API 요청, 결과 렌더링, 오류 처리

## HTML 요구사항
- 페이지 제목과 언어를 한국어(`lang="ko"`)로 설정한다.
- 텍스트 입력은 `textarea`를 사용한다.
- 입력창과 버튼에 명확한 레이블을 제공한다.
- 결과 영역에는 감성 라벨, 신뢰도, 분석 이유를 각각 구분해 표시한다.
- 결과 영역과 오류 영역은 적절한 `aria-live` 속성을 사용한다.

## JavaScript 동작
1. 분석 버튼 클릭 시 입력값 앞뒤 공백을 제거한다.
2. 비어 있으면 오류 안내를 표시하고 API를 호출하지 않는다.
3. 2,000자를 초과하면 오류 안내를 표시하고 API를 호출하지 않는다.
4. 정상 입력이면 기존 오류와 결과를 정리하고 로딩 상태로 바꾼다.
5. `fetch('/api/analyze', { method: 'POST', ... })`로 요청한다.
6. HTTP 상태 코드와 응답 JSON을 확인한다.
7. 성공한 경우 감성 라벨, 신뢰도, 분석 이유를 화면에 표시한다.
8. 실패한 경우 사용자용 메시지를 표시하고 다시 시도할 수 있게 한다.
9. 완료 후 버튼을 다시 활성화한다.

## API 계약
요청:
```json
{
  "text": "오늘 정말 즐거운 하루였어."
}
```
성공 응답:
```json
{
  "success": true,
  "result": {
    "sentiment": "positive",
    "confidence": 92,
    "reason": "즐거운이라는 긍정적인 표현이 사용되었습니다."
  }
}
```
오류 응답:
```json
{
  "success": false,
  "error": {
    "code": "INVALID_INPUT",
    "message": "분석할 텍스트를 입력해 주세요."
  }
}
```

## 안전한 화면 출력
- AI가 반환한 `reason`을 `innerHTML`로 삽입하지 않는다.
- `textContent`를 사용해 일반 텍스트로 표시한다.
- 응답 데이터의 자료형과 필수 필드를 확인한다.
- 예상하지 못한 감성 라벨은 화면에 표시하지 말고 오류 처리한다.

## 완료 기준
- 입력 글자 수가 실시간으로 표시된다.
- 빈 입력과 2,000자 초과 입력이 차단된다.
- 요청 중 버튼 중복 클릭이 차단된다.
- 성공·실패 응답이 각각 올바른 UI로 연결된다.
- 브라우저에서 API 비밀 키가 확인되지 않는다.
